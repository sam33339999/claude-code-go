> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
>
> **本專案的執行方式**（負責人全域 CLAUDE.md）：主 session 依序實作；Task 3（後端完成）時開 reviewer subagent 審那一段 diff；Task 6、合併前再審整個分支。
>
> **前置條件**：`docs/superpowers/plans/2026-11-20-model-switch.md` 的 Task 1（`engine.MainTarget`、`CacheSafeParams.Client`）與 Task 3（`modelSwitcher`）已完成，在同一個分支 `feat/model-switch` 上接著做。

**Goal:** `/btw [--tier <名>] <問題>` 在主腦執行中也立即平行回答，繼承主腦脈絡並共用快取，只能用唯讀工具與「只能附加」的 TodoWrite；答案以旁注顯示、不進主腦歷史，完成後 ctrl+y 可交給主腦。

**Architecture:** engine 新增三個每次查詢的開關（`ToolFilter`、`NonInteractivePermissions`、`NoCompaction`），並修正非主腦查詢搶走主腦佇列的 bug。TodoWrite 依 `UseContext.TodoAppendOnly` 改為附加。TUI 以 `btwSession` 管理一條獨立的 engine 串流（`tea.Cmd` 逐段讀），旁注是 TUI 本地訊息。

**Tech Stack:** Go 1.26、bubbletea v2、既有 `msgqueue`、`engine.MainTarget`。

**Spec:** `docs/superpowers/specs/2026-11-20-btw-design.md`

## Global Constraints

- btw 的請求前綴（工具 schema、system、歷史）與主腦對應請求**位元組一致**；工具清單不刪，只在執行時擋。
- btw：`NoWriteBack: true`、`QuerySource: "btw"`、`MaxTurns: 10`、自己的 `CompactTracker`、`NoCompaction: true`、`NonInteractivePermissions: true`。
- 放行：`IsReadOnly(input)` 且不在排除清單（`AskUserQuestion`、`EnterPlanMode`、`ExitPlanMode`、`Sleep`、`agenttype.CoordinatorOnlyTools`、`Agent`），或 `TodoWrite`（附加模式）。被擋 → `tool_result` 錯誤「<name> is not available in /btw (read-only)」。
- 權限：btw 只用 `Checker.CanUseTool`（不呼叫 `RequestPermission`，不跳對話框、不記錄拒絕）；Ask 視為 Deny，reason「needs permission; ask the main conversation instead」。
- 脈絡：主腦執行中用該次查詢 `UseContext.CacheParams` 快照；閒置時用 `GetMessages()` ＋ 與 `startQueryCmd` 相同的 system prompt。
- 估算超過目標的自動壓縮門檻 → 拒絕：「the conversation is too large for /btw; ask the main conversation instead」。
- 同時只允許一個 btw；btw 不進主腦歷史、不進 transcript。
- Esc：btw 進行中先中斷 btw；第二次 Esc（btw 已停）才中斷主腦。
- ctrl+y：主腦執行中 → `ModePrompt` 入列且 `Origin: "btw"`；主腦這一輪結束仍未被取走 → 轉為待附加；主腦閒置 → 直接存為待附加，附在下一則使用者訊息前面，可按 Esc 取消。
- UI 文字英文；TUI 測試用「詞」斷言；檔案 ≤800 行、函式 ≤80 行；GoDoc；`make docs` 後補 Design Notes。

## Review Focus

1. **btw 的工具 schema 與主腦不同**（例如因為某處依 `ExcludeTools` 過濾）導致吃不到快取。→ Task 1 `TestBTW_RequestPrefixMatchesMain`（比對同一份 params 的 `buildRequestWithModel` 輸出，除尾端外位元組相同）。
2. **主腦在 btw 執行期間結束、又被使用者送出新訊息**：btw 繼續用它出發時的快照，不讀到新的歷史，也不影響主腦。→ Task 4 `TestBTW_MainTurnEndsDuringBTW`。
3. **btw 的 TodoWrite 與主腦同時寫 todo**：不能遺失主腦的更新（附加需在同一次 SetState 內讀改寫）。→ Task 2 `TestTodoWrite_AppendConcurrentWithReplace`（-race）。
4. **使用者在 btw 進行中執行 `/clear` 或 `/model`**：btw 結果不得寫回、ctrl+y 交出時仍只接到尾端。→ Task 4 `TestBTW_ClearDuringBTW`。
5. **連按 ctrl+y 兩次**：只交出一次。→ Task 5 `TestBTW_SendOnce`。
