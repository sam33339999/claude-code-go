# `/btw`：平行的旁支問答

主腦正在處理任務時，`/btw <問題>` 可以另外問一個小問題，**不打斷主腦**。答案以旁注顯示，不會進入主腦的對話；看完可以選擇交給主腦。

設計背景：`docs/superpowers/specs/2026-11-20-btw-design.md`。

## 用法

```
/btw retry.go 的 backoff 上限是多少？
/btw --tier lite 這個函式在哪裡被呼叫？
```

- 主腦在跑時也會**立刻**開始（不進 slash 指令佇列）；主腦閒置時也能用。
- 同時只能有一個 `/btw`。
- `--tier` 可以指定等級（lite / pro / max、舊別名、`provider:model`）。不指定時用主腦目前的模型，才吃得到主腦的 prompt 快取；指定別的 provider 或模型就吃不到。

## 它能做什麼

- 看得到主腦目前的對話脈絡：主腦在跑時用這一輪請求的快照，閒置時用完整的對話歷史。
- 只能執行**唯讀工具**（Read、Glob、Grep、WebFetch 之類）。其他工具（Write、Edit、Bash、派 sub-agent……）會回「not available in /btw」；會跳對話框或改權限模式的工具（AskUserQuestion、Enter/ExitPlanMode）也不行。
- 需要詢問權限的呼叫直接拒絕，不會跳對話框，也不影響主腦之後的權限判斷。
- 可以用 TodoWrite（不需要權限確認），但**只能新增**到主腦的 todo 清單尾端（標 `[btw]`），不會改動主腦既有的項目。主腦下一次整份更新 todo 時，這些項目可能被它的版本取代。
- 最多 10 輪工具往返；不做壓縮——對話太大時直接拒絕。

## 按鍵

| 狀態 | 按鍵 | 作用 |
|------|------|------|
| btw 回答中 | Esc | 停止 btw（主腦繼續）；再按一次 Esc 才中斷主腦 |
| btw 完成 | ctrl+y | 把「問題＋回答」交給主腦 |
| btw 完成 | Esc | 關閉提示（不交給主腦，也不會中斷主腦） |
| 有待附加的備註 | Esc | 丟棄備註 |

## 交給主腦（ctrl+y）

- **主腦在跑**：在下一個工具邊界接到主腦對話的尾端（不動前綴）。如果主腦這一輪沒有再碰到工具邊界就結束，會改成「待附加」。
- **主腦閒置**：不會自動讓主腦開始回應；輸入框上方顯示「1 btw note will be attached…」，附加在你下一則訊息的前面一起送出。

btw 的內容不寫進 session 紀錄，resume 之後看不到；交給主腦的部分會隨主腦的對話保存。
